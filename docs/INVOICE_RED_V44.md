# Work OS · 发票红冲及税率字典（Schema 44）

## 已实现范围

- 红字发票作为**独立原始凭证**登记，原始文件须先进入 Work OS 原件档案，再引用 archive_file_id。
- 每张红票绑定一张已有蓝票，保存红票号码、原币金额、税额、红冲原因和开具日期。
- 按红票自然身份和来源键防重；累计金额或税额不得大于蓝票原额。
- GET /api/invoices 增加 credited_amount / net_amount / credited_tax_amount / net_tax_amount，不覆盖蓝票原始金额。
- GET/POST /api/invoices/red；GET/POST /api/tax/rates。
- 税率字典按生效日期版本化、要求来源依据和记录人；旧版不覆盖，后续生效版本可截断旧开放区间的**查询有效期**。
- 月度票据流水按**红票开具月份**列示红字原币金额；已关闭蓝票月份不回写。
- 现有发票认领上限改为蓝票净额；对已认领大于红冲后净额的情况报异常，不擅自修改历史认领。

## 明确未实现的核算动作

1. **红票不是经济业务退款。** “退货、折让、重开、更正”在票据层面登记；收入/成本/应收应付调整仍须对应原业务事件与复核分录，不从红票金额直接推断。
2. **发票内认领不等于税局认证抵扣。** 原蓝票已抵扣且后来红冲时，只提示“需要进项税转出复核”，不自动确认可抵扣税额。
3. **单人本地管理登录不构成独立审批。** 具名账号、强制角色隔离、请求人和审批人分离、完整审计轨迹仍是上线阻断项。
4. 原件仍需进行 R2 / Neon / NAS 的真实备份及恢复验收；单元测试不能替代。

## 迁移验证与上线阻断项

- 现有生产库基线：Schema 43。仅新建 invoice_credit_notes / tax_rate_rules、索引，追加 schema_migrations=44，不对旧发票和总账做 UPDATE。
- 人工审核迁移文件：backend/migrations/44_invoice_red_and_tax_rates.sql。
- 已通过的验证：隔离数据库分支的 SQL DDL 和自动化 SQLite / disposable PG 测试。
- **禁止在生产服务仍运行 Schema 43 版本代码时先单独升级数据库。** 旧服务启动预检查严格要求当前 schema 等于代码版本，先制定维护窗口和原子切换方案。
- 在生产数据和环境备份、可恢复性、审批权限、部署目标及真实业务复核都确认之前，不合并上线本功能。
