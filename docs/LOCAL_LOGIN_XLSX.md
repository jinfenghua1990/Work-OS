# Work OS 本地登录与 Excel 导入（开发交付说明）

本轮实现的是**单人本机开发版**，不是可直接公网部署的多用户财务系统。当前代码、测试及演示环境仍以本地为主，正式 Neon/PostgreSQL 不直接修改。

## 本地密码登录

1. 在项目根目录运行 `python backend/set_local_password.py`，输入两次管理密码（至少 12 字符，输入不回显）。
2. 把脚本打印的 `WORKOS_AUTH_PASSWORD_HASH=scrypt$...` 完整写进根目录的 `.env`；**仅保存密码哈希，不存明文密码**。
3. 运行 `python backend/run_offline.py`，另开终端运行 `npm run dev`。打开 `http://127.0.0.1:8085` 登录。
4. 8 小时会话过期需要重新登录；退出登录会作废服务端内存中的会话令牌，API 服务重启也会令所有会话失效。

**重要边界：**
- 未配置 `WORKOS_AUTH_PASSWORD_HASH` 时，保留旧版无密码**本机离线模式**，界面会警示；不是已经设好登录。
- API 强制监听 `127.0.0.1` 等回环地址。设置 `WORKOS_HOST=0.0.0.0` 会拒绝启动，即使已设置密码也不能把本地 HTTP 端口暴露到公网。
- 本地模式加入 HttpOnly/SameSite 严格会话 Cookie、错误密码节流及非本机页面的跨站 POST 阻断，但不具备用户分角色权限、HTTPS 安全网关、SSO、审计安全策略或跨设备登录；这些属于正式多用户上线前的单独工作。
- `.env` 与本地业务数据库、原始文件均已忽略 Git 版本控制。公开仓库禁止提交实际密码哈希、数据库连接串及财务原件。

## Excel (.xlsx) 导入

咖啡销售、银行流水、自行车销售页面接受 UTF-8 CSV 或 **XLSX 第一张工作表**。前端通过 `/api/import/preview-xlsx` 本机预览 XLSX；检查后点击确认，相关业务才走原件归档、业务关联及财务过账。

- 解析共享文本、内联文本、数字及常见 Excel 日期格式，保留稀疏列。
- **不执行 Excel 公式**，也不信任可能过时的公式缓存。公式或错误单元格会提示重新另存为**值**以后再导入。
- 旧二进制 `.xls` 需另存为 `.xlsx`；宏文件 `.xlsm` 不支持。
- 限制：压缩文件最大 20MiB；最多 10,000 非空行、160 列；不适合未经拆分的超大月度汇总。
- 页面已有的订单行唯一键规则和成本复核仍生效；解析成功**不代表库存充足、凭证匹配或已成功过账**。
- 自行车导入新业务行按照「渠道＋ALSVID 采购引用＋外部销售订单＋来源行号」构成稳定键，不再以原文件名标识；旧历史来源键未迁移，首次导入历史数据必须先做只读对账，避免重复。
- 银行流水仅含无独立流水号的来源行仍需额外人工确认，不能仅靠文件名+行号断言没有重复。

## 本地测试

```bash
python -m unittest discover -s backend/tests -v
npm ci
npm run build
```

新增测试覆盖：HTTP 登录/退出/限流/CORS-源校验、XLSX 字符串/日期/公式、以及自行车销售归档与同单防重。全部使用临时 SQLite，不连接或修改正式 Neon。
