# Work OS：银行流水防重与凭证核对

## 自动导入规则

Work OS 的统一银行流水属于财务中心，咖啡、自行车、展会共享，不为各业务建立独立银行账本。

- 从银行 Excel/CSV 导入时，**真实银行账户名、交易日期、银行签发的流水号/交易编号**为自动入账必填项。
- `strict_identity=true` 模式由后台把「账户＋日期＋银行流水号」规范化为稳定哈希身份 `bank:v3:<sha256>`；文件名、Excel 行号、保存路径变化不产生新交易。
- `bank_reference` 空白、账户未指定或日期无效的行**不允许自动入账**，先显示在复核区。用户应补充银行原始交易标识，不能随意虚构编号。
- 同一身份金额、币种、收支方向或摘要与已登记数据不一致时，**拒绝覆盖**，由人工核对银行原件和历史入账。
- 对历史 `file.csv:row` 等旧来源键，系统会按相同「银行账户＋日期＋交易流水号」查找，匹配的既有交易不再重新导入；同一标识关联多条历史记录时拒绝导入并要求先处理历史重复。
- **不修改已入账的历史银行交易**，不自动分配资金、不把银行收付等同于销售收入或费用，不擅自修改已封账月。
- 尚有调用旧版 `POST /api/bank/import` 的系统可能未提供 `strict_identity`，为了兼容保留其旧逻辑。正式跨系统接口必须统一使用严谨的来源身份规则，不得依赖旧版文件行号。

## 文件和业务记录完整性核对

财务中心 → 发票管理 → **统一原始凭证档案 → 核验档案完整性**：

- 只读计算档案现存文件的 SHA-256，与数据库保存的文件哈希、文件大小及索引核对。
- 对已关联的银行流水、咖啡采购、咖啡销售、自行车销售、进销项发票检查对应业务记录是否存在。
- 列出已存储但尚未关联业务的文件数，以及已有业务记录尚未关联原件的数量。
- 单次最多核验 **2,000 份原件、10,000 条关联**；超出返回 `partial`，不能显示为全面通过。
- 旧数据未建立关联，不代表文件已经丢失；核对结果不能自动重建文件，也不能证明发票或银行来源真实性。
- 未实现远程安全授权、法规 WORM 锁定、独立异地备份、真实银行直连接口或税局票据认证，以上均需单独验收。


新增离线测试覆盖：重命名银行文件不重复、金额冲突禁止入账、缺少流水号拒绝自动入账、旧 CSV 键跨文件识别、旧重复交易需人工复核、原件文件完整性、被损坏文件、失效业务单关联、历史银行记录缺少原件关联提示。

本批次测试只使用临时 SQLite/临时文件夹，不修改 Neon 正式数据库。
