# 咖啡售后：仅退款与实物退货的不同处理方式

## 已开发

- 新增 `sales_refunds`（schema v40），登记原销售行、平台真实退款单号、退款日期、金额、原因和收款未收状态。
- **仅退款**：借记「销售收入」，贷记「应收账款」或「应付客户退款」。不创建库存入库、不恢复 FIFO 成本；有原始退款凭证时先归档并关联业务记录。
- **实物退货**：按原 FIFO 层真实恢复成品和对应包装；只冲回未因既有退款/退货冲回的剩余收入，不能让累计冲回超过原销售金额。
- 同一来源退款单号重复提交返回已有记录；同一个退款单号传入不同金额、原因、原销售行，则阻止覆盖并要求人工核查。
- 若商品已经卖出但收款部分到账，新增仅退款先冲减未结应收，超出部分形成客户退款应付；后续还需通过统一银行流水核销。
- 原销售行是否还有可退实物数量与可退财务金额**分开统计**，物理库存状态不取决于是否已全额退款。
- UI：咖啡销售退货页新增折叠的「仅退款（不退货、不增加库存）」操作，需填写平台退款号、退款金额、日期和原因。原始凭证建议上传；未关联文件会在档案核对里显示。
- 旧 `sales_returns` 记录和原月账务不自动改写。

- 红字发票/税额调整及税务申报确认（单纯内部仅退款记录不等于税务红冲）；
- 所有已结账历史退款迁移与差异核对；
- 退款原因、审批权限和电子会计档案合规校验；
- 正式 Neon 数据库 schema v40 迁移和云端备份恢复演练。

**验证方式**：`python -m unittest discover -s backend/tests -v`；`npm ci && npm run build`。验证数据使用隔离 SQLite 和一次性 PostgreSQL 18，正式 Neon 生产库不写入、不做自动迁移。
