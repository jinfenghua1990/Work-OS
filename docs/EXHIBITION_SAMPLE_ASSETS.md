# 展会样品核算调整：发出仅转资产，实际耗用才认费用

数据库 schema 版本：39。该修改只针对**新发生**的展会样品发出，不能自行重算旧账。

## 新样品流水

1. **样品发出**：咖啡成品及需额外扣减的包装盒按 FIFO 从主库存扣减；总账借「展会在外样品」(`inventory:exhibition`)，贷「存货」(`inventory`)。该动作本身**不计损益费用**。
2. **样品归还**：从原发出 FIFO 层恢复成品/包装盒库存；总账借「存货」、贷「展会在外样品」；归还本身不形成利润。
3. **样品实际消耗、赠送、损坏**：对尚在外的样品逐笔登记实际数量、日期、来源键、原因；按原 FIFO 成本借「项目样品费用」、贷「展会在外样品」。销售用途必须通过真正销售/成本流程入账，不能作为此处的“消耗”。
4. 每个外发单始终满足：**发出数量 = 已归还数量 + 已确认耗用数量 + 尚在外数量**。系统防止重复来源键、重复计费用、超数量归还或超量消耗。
5. 账务继续记录到原公司主体、**咖啡业务线**及具体展会项目维度，同一笔分录只计一次，公司合并利润与项目利润不得重复加总。

## 老数据不篡改

- 旧样品发出记录新增 `accounting_treatment=legacy_expensed`，旧总账和旧月利润不重写。
- 旧样品仍按老机制归还冲回已记录的费用，不能再通过新「实际耗用」接口重复计费用。
- 新记录使用 `accounting_treatment=asset_transfer`，两者按处理方式区分。
- 若历史样品原先不应直接费用化，需在对账确认后通过**受审计的更正凭证**处理，不能数据库直改。
- 新增 `sample_dispositions` 和 `sample_disposition_layers` 保存处置事实及逐批次成本，损耗需要有可信业务凭证。

## 财务报表

- 资产负债表新增在外样品资产，按指定历史截止日还原当时发出、归还及已消耗的成本。
- 展会预算对比与月度项目利润：新样品转移不属于费用，实际处置才进入项目样品费用。
- UI 显示：发出、归还、已耗用、在外数量、原发出成本及在外资产额。
- 修复样品归还和凭证查询中两个 SQLite `rowid` 依赖，避免 PostgreSQL 查询出错。

## 验证和限制

本地 SQLite 自动测试覆盖成品＋包装盒、FIFO 发出、部分归还、实际耗用、全部结清、防重及按日期的样品资产恢复。

**仍未完成**：真实会计凭证/税务单据外部证据核验、旧展会数据迁移与重分类、B2B 或现场销售对账、远程用户身份权限、Neon 数据库正式切换和带历史账的端到端结账验收。这些需要另行完成，不得当作已经投产。
