# 实施与验收路线

> 本文记录历史实施与验收状态，文中出现的 schema 版本（如 36）是当时快照。当前代码基线为 **Schema 46**；最新变更见 `README.md`、`backend/migrations/46_legacy_raw_records.sql` 与 `docs/PRODUCTION_ROLLOUT_V45.md` 的 46 附加项。

## 交付顺序

1. **已完成（本地开发基线）**：React/TypeScript 工作台、Python HTTP API、SQLite 持久化、Vite 本地代理和可重复执行的 schema migration（当前版本 36）。后端现提供可选 psycopg/PostgreSQL 适配；隔离 Neon `work-os-local-dev` 分支已初始化到 schema 36，Vite 代理通过本地 API 完成健康、采购、银行流水、平台收入和库存预警只读请求。默认无数据库配置时仍用本地 SQLite；SQLite 与 Neon 不自动复制数据。Neon 上业务写入流程和交易回滚尚待完整验收。
2. **部分完成（咖啡）**：采购录入、分批收货、FIFO 库存层和带原币标记的库存流水查询、可维护的 SKU 包装规则、仅适用于已登记包装 SKU 的安全库存预警线（仅提示，不自动采购）、CSV 销售本地预览/列映射/逐行过账、按规则扣减包装库存、稳定来源键防重、错误行复核、借贷平衡的采购/销售凭证；销售来源行重试会对照已过账的日期、SKU、数量、单价、渠道、业务维度及客户，只有内容一致才返回幂等成功，同一来源键内容改变会拒绝并要求销售退货或复核更正，防止静默漏账；CSV 中重复的来源行号会在预览阶段拒绝，避免两行被归并为同一来源交易；采购单以采购数量、到货数量、凭据采购总额、按到货比例计算的已到货金额和未到货金额供数量及金额核对；到货数量可在原收货记录中修订并同步库存与应付，不设独立采购退货流程；修改前要求应付和人民币账面值记录齐全，付款、发票关联、库存已耗用数量不能被修改金额/数量冲穿。存货估值仍按不含税单位成本独立核算。咖啡经营分析现按月按 SKU 汇总销售净收入、可追溯 FIFO 成本和毛利，并计入当月可追溯销售退货；有未估值销售行时会标明毛利不完整。销售 CSV 可选映射渠道字段，经营分析按渠道汇总毛利；历史销售缺少渠道的记录归入“未标注”。库存月均余额快照未建立，暂不计算库存周转天数。销售退货现可按销售行和原 FIFO 库存层追溯，退回成品与可单独归还的包装，冲回收入、应收/客户退款应付、销售成本和存货；旧销售若没有精确批次成本关联会被拒绝自动估价。销售退货使用稳定来源键防重。工厂已含包装的 SKU 不扣包装库存；未配置规则的 SKU 不允许过账。无法从旧数据追溯的库存流水币种标记为 UNKNOWN，不反推猜测。
3. **部分完成（财务）**：采购、收货、发票记录原币/汇率/日期；收货与销售产生应付/应收；银行 CSV 导入与防重；流水可部分分配到应收/应付，未识别金额可暂挂待分类；发票台账可内部关联应收/应付并记录关联金额、原币/汇率和税务状态证据历史；可录入人民币经营费用并按发生日计入损益及形成应付。公共费用可按稳定来源键分批分摊至同一主体下项目，并可在未关账期间按金额部分或全部撤回：保留原分摊及撤回记录、生成反向维度重分类凭证，将金额退回可分摊余额；公司合并费用总额不变。采购、销售、费用及其凭证记录业务线、主体，费用与销售支持可选项目编码；经营报表可按这些维度筛选，并区分收入、销售成本、毛利、已登记经营费用和按已登记费用计算的经营利润；现提供截至日期的 CNY 总账试算平衡表，并支持一次性导入经复核、借贷平衡的人民币期初余额作为总账分录；期初日期必须早于既有业务凭证，后续新业务日期必须晚于期初日期。导入键幂等，导入后不可覆盖，需通过后续调整凭证更正。当前核心内部科目及经营费用科目已有基础类别/报表映射，并提供总账资产负债表试算视图；完整标准科目表维护、自由科目映射管理、子账核对和余额迁移工具仍未完成。资产负债表视图现按截止日比对人民币应收、应付和可估值库存子账与总账控制科目；历史日期缺失、未估值外币库存流水和期初明细未迁移会明确显示差额/缺口。该视图仍缺完整标准科目维护、银行余额核对、外币账簿和全面子账迁移，固定标记为非完整、不可用于法定报表；现金流量表现提供基于已导入银行流水与人工分类的直接法预览，内部转账另列并从净现金变动中排除；支持登记企业银行账户、按月录入银行对账单期初/期末余额并核对流水差异，且须记录账户清单完整性确认。因外币账户余额折算、账户变更管理与正式对账复核身份尚未接入，仍标记为登记范围结果，不作为完整法定现金流量表。银行方向无法识别时整份 CSV 拒绝，不推测收支方向。库存资产总览只汇总人民币批次，其他币种逐币种显示，不直接相加。全局账期状态连接关账记录，应收应付分别显示人民币账面余额。外币余额另按原币查阅；费用完整性已提供按月外部来源登记、费用逐笔关联、金额核对及过期检测，但操作者身份尚未认证；正式月结复核仍未完成，因此经营利润标记为登记范围结果而非完整关账实际。
4. **部分完成（财务）**：银行外币流水与应收应付需登记经复核汇率和来源；认领时按 CNY 本位币核算已实现汇兑损益，并在经营报表单列。关账前现有凭证平衡、未分配流水、外币估值检查和人工复核清单，复核键与凭证张数会随锁账保存；仍未完成银行来源格式模板和覆盖完整性的正式银行对账单调节、应付/应收正式核销流程、发票文件解析、真实税务机关用途确认集成、税额确认对会计余额的正式规则、具名权限/复核人认证；手工调整凭证已支持基本 CNY 调整，但缺乏具名审批与完整审计身份。
5. **未完成**：权限与审计用户。盘点差异支持按盘盈/盘亏过账，盘盈建立独立库存来源层，盘亏按币种 FIFO 扣减；均记录盘点凭据和损益分录，隔离账套链路已验证。采购到货数量和金额在采购单中核对；销售退货支持可追溯的本地咖啡销售行。销售退货税务凭据处理尚未完成。关账复核要求填写关账人姓名并保存复核项；同一关账请求重试幂等，但姓名为手工自报，未接入认证系统，人工核对声明不能作为独立审计身份凭据。
6. **部分完成（展会）**：本地展会项目建档、分类预算维护、项目费用按发生日形成应付与分录；样品发出按 FIFO 扣减人民币库存、包装按 SKU 规则处理并计入项目样品费用，归还时按原库存批次成本恢复库存并冲回样品费用；项目分类预算执行可汇总费用与样品耗用。项目页按项目编码和月份展示已过账收入、销售成本、毛利、经营费用及经营利润，公共费用可通过行级维度重分类分摊至项目，并支持在未关账期间部分或全部撤回；预算执行与月度损益分开展示，公司合并仍以总账分录为唯一来源。合同/收入完整性对账仍未完成；费用完整性可按来源登记并核对，但操作者身份未认证。**部分完成（自行车）**：ALSVID 采购引用、原币分期节点；批次数量与可归属物流/关税/仓配费用可登记，按合同与费用汇率折成人民币并按辆等额形成参考到岸成本；资本化费用形成存货资产与原币应付。进口增值税仅留待确认记录，不进成本、不生成抵扣分录。自行车现可录入带稳定 ALSVID 来源键的实收数量并按采购合同金额确认 CNY 存货；销售 CSV 幂等导入要求订单关联和实收可售数量，保存原币收入与汇率，按该批次合同及已登记可资本化费用结转 CNY 销售成本，生成平衡总账分录及原币应收。实收数量由用户按外部来源键确认，尚无 ALSVID API/附件核验；外币银行结算已实现 CNY 汇兑损益，银行对账和费用迟到后的成本调整仍未完成。
7. **未完成**：旧系统只读抽取、来源对账、差异复核、迁移演练和正式切换验收。本地检查了可用的 Codex/Qoder/NAS 项目目录，未找到 CoffeeBear 源码或可识别的历史账套导出；当前没有导入任何旧系统数据。迁移实现须等取得真实旧系统来源后再按只读抽取、逐项对账和演练执行。

## 第一条端到端验收链

当前已验证的开发范围：Python 编译、前端 TypeScript/Vite 构建、本地 API 启动及销售退货只读接口经 SQLite schema 29 迁移后，费用完整性和平台收入核对接口可响应；平台月度汇总现支持浏览器本地 CSV 选列、预览、账期与重复校验、逐行保存，后端明细采用原有变更历史；隔离 Neon 开发分支现已升级至 schema 36，本地 SQLite 数据库仍为独立账套，不会自动同步。schema 33 安全库存阈值只读 API 已从本地 PostgreSQL 服务返回空列表；阈值写入接口尚未进行业务写入验收。schema 34 的渠道毛利 API 已返回空期结果；本机无销售记录，未写入样例业务数据。schema 35 手工调整凭证已在隔离临时 SQLite 库验证：平衡凭证可过账、同内容重试幂等、同键改内容/不平/关账期间均拒绝，分录查询能返回摘要；未向本地业务账套写入测试凭证。schema 36 盘点调整已在隔离 SQLite 账套验证：盘盈建立非采购来源批次，盘亏从采购 FIFO 批次扣减；10 件存货盘盈 2 后盘亏 2，余额正确回到 10；重复来源键不重复过账，超库存盘亏和同键改内容被拒绝；两笔调整各生成一张人民币盘点损益凭证。分摊撤回功能已在隔离临时数据库验证分批撤回、重复来源键幂等、超额分摊拒绝和反向维度分录。采购数量 10、收货 6 后修订为 5 的隔离 API 链已确认采购单到货金额比例、库存数量、应付余额和凭证均同步；本地账套本身没有采购单或收货记录。schema 31 的银行流水与发票外部来源系统/单据号字段已在隔离 API 验证：来源引用重复请求幂等、冲突内容拒绝，旧 schema 可迁移，字段可由查询 API 返回。schema 32 的财务操作回执已验证银行认领、发票关联在同键同数据重试时不重复过账/关联，同键改数据会拒绝，数据库只保留一条记录和一份分录。已验证关账后不能新增发票关联或更改税务状态；此前成功的关联重试与不变税务状态重试仍幂等成功，未新增审计历史。关账验证确认复核姓名与六项检查键会保存，同一人同一清单重试不重复创建关账记录，不同姓名不能覆盖；界面姓名是自报文本，非认证身份。销售退货过账的样本业务链尚未复核。外币银行认领按经复核的银行汇率和往来账面值计算结算汇兑差额；未分类流水不臆测损益。跨系统生产访问仍需身份认证、角色与业务范围授权；税务机关集成、正式银行调节及具名认证的关账复核仍未完成，因此不是完整可投产财务系统。跨币种库存成本折算、外币销售收入的期末重估、未实现汇兑损益和汇率波动调整仍未实现；外币批次不应与其他币种批次合并核算。

验收必须覆盖重复导入、部分收货/付款/开票、未开票销售、未认证进项、杂项银行流水、销售退货、负库存、跨币种与展会合并去重；采购到货数量修订需在有真实收货记录时核对数量、库存和应付同步结果。银行对账汇总和保存时均按账户名称、币种与账期筛选流水，防止同名账户的不同币种流水混入差额；该筛选行为已修复，正式银行来源调节及账户范围审计仍未完成。不能用静态页面或仅有 UI 的演示代替账务验收。

## 本地开发

本地前端固定端口 5175，API 固定端口 8106；当前通过 `npm run dev:full` 和 `backend/run_offline.py` 启动，强制绑定回环地址、使用 SQLite 开发账套并跳过 `.env`，API 健康接口已确认 `database_backend=sqlite`。运行时不加载 CDN、远程字体或图片。密钥只放环境变量或未跟踪的 `.env`；本地离线启动不读取密钥。默认数据库为忽略跟踪的 `backend/data/workos.sqlite3`；SQLite schema 有幂等版本迁移。Neon 与 SQLite 不自动同步；旧库迁移须另行设计并对账。销售和银行 CSV 在本机解析；各渠道与银行模板仍需适配。每个阶段记录实际运行与验收状态，不把设计文档表述为已完成系统。

经营总览的近期动态和全部动态现从本地采购单、库存流水、费用和银行流水生成并按发生日期倒序；列表搜索覆盖摘要、对手方和状态。动态不调用外部数据源；未接入的业务来源仍不会显示为已有数据。

经营收入趋势图按月读取最近六个月已过账的本地经营报表，展示销售收入与销售成本；正值向上、退货导致的负值向下。业务线贡献卡按本月咖啡、自行车、展会、公司其他及未归属维度读取销售净收入和占比。所有金额均沿用报表 CNY 总账口径；本地 API 对上述五种业务线筛选均有响应。
