# 工作台交互规范

## 全局框架

- 顶部一级导航：咖啡业务、自行车业务、展会项目、财务核算中心；不使用多级侧栏树。
- 顶栏常驻当前账期和状态（实时预估 / 已结账实际）、全局待办数量、用户入口。
- 顶栏待办计数从未分配银行流水、缺少 CNY 账面汇率的外币记录、逾期应收应付和待核实税务状态实时汇总；待办列表可跳转到财务中心对应工作区，API 离线时明确显示不可用。
- 工作台使用顶部二级 Tab、主列表/看板、右侧抽屉完成新增与详情，不因常规录入离开当前上下文。
- 金额显示原币、币种与折算口径；财务金额不能用二进制浮点数计算。
- 银行流水和进销项发票通过财务 API 统一登记，供未来其他 Admin 后台引用；跨系统记录以 `source_system + source_document_id` 稳定识别并支持幂等重试，Work OS 保持财务状态与总账的唯一权威来源。当前 API 只绑定本机，尚未实现身份认证、角色权限及业务线范围授权，不能直接向其他系统开放生产访问。

## 咖啡业务 `/coffee`

采购单录入凭据采购总金额，并直接显示采购数量、已到货数量、按到货比例计算的已到货金额及未到货金额，供数量和金额核对；存货仍按不含税单位成本计价；到货按收货记录登记，数量可直接在原收货记录中修订并同步库存与应付；系统不提供独立采购退货流程。销售退货按原销售行和 FIFO 成本恢复实际退回的成品与包装，已收款部分形成客户退款应付；无法追溯旧销售成本时拒绝自动估价。库存管理分别追踪成品和盒子，提供安全库存预警、入库/销售出库/销售退货流水及本地 CSV 销售导入。导入必须幂等，并由 SKU 包装规则决定是否扣盒。经营分析展示单品与渠道毛利、库存周转和动销。

## 自行车业务 `/bike`

以 ALSVID 采购单号作为外部采购稳定引用，不重建 VIN、BOM 或实体库存权威数据。当前可登记合同批次数量、合同币种金额和分期付款节点；付款节点只能在计划日期当日或之后确认到期，确认日期会留存。并按来源键登记海运、关税、海外仓及其他可归属成本；合同与费用按汇率折成人民币后按辆等额计算参考到岸成本。进口增值税独立留档，不计入成本，也不自动确认抵扣。自行车销售 CSV 按渠道稳定行号关联 ALSVID 采购引用，原币收入按汇率折算 CNY，批次成本按合同及已登记费用计算；系统先要求录入引用外部来源键的实收数量，再限制销售不得超过实收未售数量。实收确认生成存货资产分录；销售生成收入、成本、库存和应收分录。实收目前由用户录入，未直连 ALSVID 或验证附件；外币收入期末重估、未实现汇兑损益及银行对账仍待完成。外币流水与往来核销时已按复核汇率计算并单列已实现汇兑损益。

## 展会项目 `/exhibition`

本地版本已支持项目建档、分类预算、按项目归集发生费用，以及样品按 FIFO 发出、归还和成本冲回；预算执行单独展示，预算余额不作为利润。项目页可按月查看已过账收入、销售成本、经营费用和经营利润。财务中心允许把公共费用按金额分批分摊至同一主体下项目；系统生成行级维度重分类凭证，项目取得相应费用，公司损益合计不变。未关账分摊可按金额部分或全部撤回，生成反向维度凭证并将金额退回可分摊余额，原记录保留；撤回操作人当前未接认证。项目完整合同管理、样品损耗审批仍待实现。

## 财务核算中心 `/finance`

包括银行流水认领、应收应付、销项/进项发票、平台收入与申报核对、会计分录、库存成本结转、经营报表和月结。平台核对按月和店铺登记平台交易总额、退款、补贴、平台费用、结算、银行到账及申报销售额；可逐笔手工登记，或在本机导入平台月度汇总 CSV：自动匹配/手动映射平台、店铺、交易总额、退款、补贴、平台费用、结算、银行到账与申报销售额字段；导入前校验账期、金额、操作人及同文件重复的平台/店铺，逐行展示结果。每行应为一个平台、店铺、账期的月度汇总，不是订单明细；未提供凭据列时以本地文件名和行号留存索引，系统不保存上传文件。净额和申报金额只作对照，不自动推定税务口径；目前没有平台或税务系统直连接口。银行流水、发票、业务单据分别建模，通过分摊/认领关联，不互相替代。关账前逐项显示凭证平衡、银行未分配/暂挂、库存币种余额、未结往来估值、费用归属、发票税务状态与汇兑信息，并提供前往对应工作区的入口；阻断项未清除时拒绝锁账，人工复核项和凭证数量随期间记录保存。关账后记录只读，调整凭证和具名用户权限仍待实现。

## 共用交互

- 所有列表支持按业务线、主体、期间、状态筛选；导入展示预览、错误行和重复检测结果。
- 新建、编辑、查看优先使用侧滑抽屉；状态变化保留操作者、时间和来源。
- 明确区分草稿、待确认、已确认、已关账；预估数据不可伪装为最终实际。
